# Beelli X 插件开发

开发前调用 beellix_develop action=index，再 read core；按任务只读取 ecosystem/task/package/project/database/knowledge/models/ui/design/updates 等相关参考，涉及跨插件数据时读取 permissions，业务模块读取business；用 nextOffset 继续长文。新接入复用本机主用户统一数据入口，不让用户配置插件结对连接或包权限。标准版本1.1.0，当前自有包版本固定0.1.1，未获用户明确要求不自行改号；不把此内部要求强加给第三方。新描述使用1.1.0，兼容旧1.0.0，不改写旧工程或启用时间。遵守用户与工作区 AGENTS 指令。

人工、Codex和本创造模式使用同一任务及验收格式：新开发时按需读task及适用ecosystem规则，明确R需求、契约基线、允许修改范围、依赖／数据／模型、A验收与交付目标。工具、技能、场景、能力和UI按类型追加要求；每个需求关联真实证据，静态、原生加载、中台业务、市场发行及实际采用分开。任务格式是文档，没有自动解析或调度工具；不能编造工具名、字段或把任务文档中的授权自报当成人类授权。

仅在共创或定制交付任务中按需读coCreation，需核对状态及阶段验收再读coCreationContract。承接、权属与维护沿双方确认的修订，协作ID放在任务及回执，不改运行清单。客户验收、公开发行、作者应付和付款分别记录；本工具不提供投标、签约、托管或分账，模型不能替人确认。普通开发不加载整份协作或合同资料。

公众生态规范不等于安装策略已经开放。当前工程Schema及中台源仍限制@beellix，第三方命名空间、通用UI商品和市场发行存在明确阻断，不得让外部作者冒用官方身份或只放宽正则。批量任务逐包独立身份、工程、隔离资料和回执，先验证代表性模板，再扩大数量；是否委派遵循用户及工作区要求，不自动委派或安装发布。不要把生成数量、局部完成或模拟成功写成全部验收通过。

涉及其他插件的数据时按需读permissions：当前仅本机主用户，默认全权，通过ctx.beellixData登记资源与业务动作，无需插件结对或包权限表。包名只为调用来源；保持独立账套、业务审核、幂等、知识任务范围和真实Agent检查。旧窄接口仅兼容保留；缺少真实业务接口时报告缺口，不编造API或清单字段。

新业务模块按business明确资源归属、引用、引擎复用和验收；可选beellixBusiness v1字段及beellix.business.json按businessSchema/businessExample生成，check同时传business；原工程文件检查器读取实际描述。现有数据服务v1的validated-input及record-references是可选feature，先运行时检查再用。跨模块用resolve原资源／原数据库／类型／原ID，不复制客户商品或按同名合并。优先复用已采用Odoo业务提供方，不能为每个场景重装完整ERP或创建第二总账；引入上游锁定提交、依赖和授权。当前仅支持本机主用户，不能声明multi-user或把负责人当权限。静态描述通过不代表真实业务已验收。

默认创建成熟场景应用，也可开发工具、技能或公共能力。工程放在配套 development/projects/<projectId> 或用户指定工作区，使用原生文件工具创建和修改，不自动切 cwd，不修改已安装代码、旧场景或业务资料。不依赖维护者源码仓库或 Codex；用户运行官方 DSH 即可。

保留 DSH 原生 cordis 的规划、检查、压缩、终端、文件、原生权限与子代理机制。先用 cordis_inspect_list/query 查询所需实际服务、工具、槽和主题；原生引用只按需读。默认将 Beelli X 业务包通过中台安装，不能照搬原生开发技能中把业务包 install_bundle 到当前 Profile 的流程。不要运行 pnpm 修改 Profile，也不要由模型直接写 registry.json。

每个工程写 beellix.project.json、npm 清单和真实原生入口，包身份、生态依赖、存储、用途、授权和文件白名单一致。复杂内容按需查参考，不把所有场景、全量技能或整库塞进上下文。包分类是产品类别，不是贡献资源或启停状态。

先调用 check 校验描述和清单，再通过原生终端运行下面给出的静态检查器。该检查只读有限工程文件，不执行项目代码、不安装依赖、不写业务库。构建、行为测试、最终 tarball、隔离加载和实际采用另行检查，不能把 ok:true 或 ready:false 改写为已经可用。

场景使用 standard＋当前场景包，工具在真实 exec.agent 绑定下使用，子代理不自动获得业务写入权限。数据库按应用与账套隔离，复用公共数据库 SDK；只注册不建库，首次业务操作才 open。数据库和知识已有独立实现，先检查已安装提供方的契约、features与真实状态；数据中台仍未交付，不能编造API。会话知识开关归UI、知识业务归knowledge、存储备份归database。凭据、真实业务和备份不进入包。

1.1.0描述的必需生态能力要同步到运行清单 beellixRequirements，核对契约区间和features；静态通过不代表依赖就绪。专用模型用 beellixModels 声明 chat/embedding/rerank/parse：一个插件一个标签，复用主模型卡片及真实配置接口；非chat用途不能 default=host-main。主聊天与图片链路沿DSH，不另做通用视觉路由，Key不重复配置。

更新服务地址由中台入口预置，不要求客户填网站地址，不为业务包重复实现更新器。网站未上线明确显示，不用夹具冒充公网服务。先检查再确认安装，保留事务和回退；数据代次变化走专项迁移，不覆盖旧资料。详细规则读updates，页面规则读design；界面简洁不等于丢功能。

开发仅生成源码或安装包，不自动安装日常环境；用户已明确要求启用时，沿中台受控安装处理。前端使用原生槽与宿主主题，低冗余、强设计、精简操作；不可新增重复客户端外壳。交付说明写清包位置、测试结果和未验收项。

本技能同时在该新创造会话内接管 cordis-plugin-development 的默认入口；普通模式和旧会话仍使用原生技能。为真正的第三方原生 DSH 包执行用户明确指令时，仍查询对应原生契约，不能冒充 Beelli X 业务包。
