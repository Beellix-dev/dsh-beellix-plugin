# 中台插件安装与分类

DSH 只安装和管理 `@beellix-ai/dsh-beellix-plugin` 入口包。Beelli X 中台安装的业务包在自己的环境中管理，不作为独立 Bundle 写入 DSH Profile 的依赖和选择清单，因此停用 UI 后也不会重新出现在 DSH 市场中。

程序位于 `Beellix/environment/node_modules`，安装登记和启停选择保存在 `Beellix/registry.json`。DSH 原生 Loader 按各包的 `dsh.bundle.patch` 创建独立 Include，原生客户端模块系统发现 UI，工具和技能仍通过 DSH 原服务注册。中台没有第二套执行引擎，也不改写 DSH 市场接口。

入口停用时释放这些加载贡献，程序、启停选择和业务资料保留；重新启用入口会按原选择接回。独立后台服务是否退出，仍由服务本身的正常生命周期决定。`data/control-plane/managed-runtime.json` 记录当前进程的加载状态，不包含业务内容或凭据。

安装包身份同时核对版本与SHA-256。同一固定版本导入不同摘要时提供“更新安装包”；重复导入相同包不提示更新，较旧版本不伪装成升级。登记中的旧摘要保留到安装成功，失败仍走原有回退。

原生Host已经导入的包换到不同物理目录（例如pnpm安装新制品）时，等待正常重启后再由原生Loader加载。不中途清理原生模块缓存，不弱化来源路径校验，也不把旧模块当成新包运行；安装结果、能力页和加载回执均如实标记待重启。其他未变化的包与业务数据保留。

已有的旧式 Profile 登记须在客户端正常退出后，只针对来源匹配中台登记目录的包迁移。保留环境、安装包、原生会话及业务文件，不允许直接移除未核验的同名第三方登记。安装与迁移需单独验收，不能由包名推断已经完成。

## 分类声明

分类标签参考用户提供的搜索与计数排布，不照搬外部市场的目录。分类描述整个安装包；`contributes`、`beellixCapability.category` 继续描述工具、技能等运行资源类型，两者独立。

旧包自动兼容：场景包显示“场景包”，工具显示“工具包”，知识库、数据库等资源能力显示“能力包”。页面只列出当前范围内确实存在的分类及真实数量。安装状态单独筛选，不作为分类；切换状态页签会恢复全部分类。

新包可在 `package.json` 增加可选声明，无需修改中台页面：

```json
{
  "beellix": {
    "catalog": {
      "category": { "id": "reports", "label": "报表包" }
    }
  }
}
```

`id` 为最多 48 个小写字母、数字或连字符，以字母开头，不能为 `all`；`label` 为最多 24 字的名称。已有公共标识采用统一名称，自定义标识随包安装自动汇总。分类参与搜索、详情返回和当前安装状态下的筛选，不决定权限、工具装配或数据位置。无包声明或没有真实依据时，不生成下载量、排行榜或安装计数。
