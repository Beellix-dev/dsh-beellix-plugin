# Beelli X 会话知识接入契约

日期：2026-10-27。状态：基本会话开关、范围、启停与重启链路已通过指定D盘客户端真实验收；在途撤销真实压力时序尚未确证，确定性回归已通过。用户确定对话知识开关交由 `@beellix-ai/dsh-beellix-plugin`；知识业务归 `@beellix-ai/knowledge`。这是两包间的中台服务契约，原生执行与权限继续归DSH；采用范围见实施状态。

## 1 唯一职责归属

| 内容 | dsh-ui | knowledge |
| --- | --- | --- |
| 对话输入区控件、空间选择与安装引导 | 拥有 | 不重复注册 |
| 会话开关状态、选择修订与持久化 | 拥有 | 只读取可信快照 |
| 可见空间、知识服务可用状态 | 消费提供方结果 | 提供并验证真实权限 |
| 原生检索工具与轻量 Skill | 不实现查询代理 | 按当前原生 Agent 作用域挂载与释放 |
| 检索、引用、内容范围与证据 | 不承接业务执行 | 再次校验并执行 |
| 资料入库、持续同步、Wiki 和图谱 | 仅提供中台承载 | 拥有 |
| DSH 模式、会话与工具权限 | 复用原生服务 | 复用原生服务 |

UI 保存的是用户的会话选择，不是资料授权。最终可读范围是“用户选定空间 ∩ 当前资料授权 ∩ 当前执行身份范围”。原生工具参数不能扩大这个交集。

## 2 最小接口提案

由 dsh-ui 提供宿主服务 `beellixKnowledgeSessions`，开发期类型随 UI 的平台类型出口发布。接口使用 `contractVersion: 1` 与明确的 features；发布前以真实官方宿主验证，名称在本稿中为拟定名。

| 接口 | 调用方 | 输入与结果 |
| --- | --- | --- |
| `registerProvider` | 已验证的 knowledge 宿主 | 包名、真实来源目录、提供方接口；返回 dispose。来源必须与中台自有资源登记一致 |
| provider `listSpaces` | UI 宿主调用 knowledge | 使用宿主可信身份，返回当前可读空间 ID、名称和实际状态；分页，不接受模型提供的用户 ID |
| provider `status` | UI 宿主调用 knowledge | 返回未初始化、可用、处理中或不可用等实际状态与原因 |
| `scope` | knowledge 工具与 Agent 适配 | 从原生执行上下文解析 Profile/会话，返回 enabled、选定空间、修订与可用性；不接受模型伪造的会话 ID |
| `subscribe` | knowledge 原生作用域 | 接收选择、停用和撤权变化，触发挂载、取消和释放 |
| `openSelection`（设计名） | dsh-ui 客户端或中台动作 | 尚未发布为独立宿主接口；当前使用唯一 KnowledgeSwitch 控件打开当前会话选择，不视为已有公共服务方法 |

保存选择是 UI 的已授权管理端操作，使用当前宿主连接身份和 expectedRevision。它不作为模型可调用的写工具公开。客户端传入 sessionId 后，UI 宿主仍须向 DSH 核对会话归属；没有当前会话时不能把选择写到最近一个无关会话。

提供方列表、状态和 scope 各自有真实结果，UI 不把“包已安装”当作“服务已就绪”。断连或未知契约时按不可用处理，不静默获得全库范围。

## 3 设置与存储

新对话默认关闭，开关只作用于该对话。重开同一对话恢复原选择，开启 A 不改变 B，也不改变所有未来会话的默认值。关闭可以保留选择列表供下次开启，但有效读取范围立即清空。

状态保存于 dsh-ui 拥有的 `config/control-plane/knowledge-sessions.json`，使用版本化格式和原子保存，字段包括本地 Profile 身份、原生 sessionId、enabled、spaceIds 和 revision。这里只保存 UI 偏好与范围引用，不存业务正文、密钥、索引或知识授权，不要求数据库先初始化。

运行中的提供方身份和可用代次另行核对，不把旧 ready 值持久化为启动后的事实。资料权限和空间删除始终以 knowledge 的当前结果为准。旧会话和日志不重写。

## 4 开启 关闭与动态变化

| 变化 | UI 行为 | knowledge 行为 |
| --- | --- | --- |
| 开启并选择空间 | 校验选择、保存修订、通知作用域 | 计算可读范围，挂载原生检索工具和轻量 Skill |
| 修改选择 | 原子提交新选择，旧快照失效 | 取消旧范围请求，按新范围接回 |
| 关闭 | 立即提交禁用并通知 | 释放查询贡献、取消在途检索，交付前拒绝旧修订结果 |
| 知识插件停用或卸载 | 保留用户选择，控件显示不可用/未安装 | dispose 提供方和工具，停止查询；保留业务资料 |
| 知识服务重连 | 根据实际提供方状态刷新 | 重新核对权限、版本与选择，不沿用旧授权结果 |
| 会话切换 | 读取目标会话状态，丢弃旧会话迟到页面响应 | 工具执行按真实 Agent 归属，不跟随客户端可变的“当前会话”变量 |
| UI 插件停用 | 停止控制服务和作用域通知，保留设置 | 缺少可信会话控制时查询关闭，不能默认放行 |

每次查询执行和结果交付前均核对会话选择修订与实际资料权限。只在点击时校验不足以防止在途旧请求交付。已经返回到 DSH 会话的内容仍归原生日志，关闭开关不擦除历史。

子代理只继承受限只读范围，并接受父范围关闭和撤权检查。知识维护会话是显式入库任务的原生执行，使用该任务自己的来源授权，不借用某个聊天历史上开启过的读取范围。

## 5 控件与对话调用

dsh-ui 使用固定官方版本可用的公开 conversation 输入区槽提供一个紧凑控件，不复制原生输入框，不修改安装文件。`conversation.input.left` 已在用户指定2.0.19-next客户端验证，仍保留其他宿主版本的兼容门禁。

点击“知识库：关闭”打开同一弹层，选择开启及空间；开启后显示空间名称或数量。缺包打开中台安装入口，未初始化打开知识页面，避免在输入区摊开组件设置。

开启时仅提供空间简述、状态、检索与引用工具，标准 Harness 按任务需要决定调用，不每条消息预检索，也不额外运行一套意图判断模型。普通改写与通用任务可直接执行；企业或项目问题只在选定范围内检索，证据不足返回缺项。

知识检索关闭时不自动开库。显式入库从中台或被明确授权的知识任务执行，开关与来源持续更新互不代替。单条消息知识引用属于后续输入协议扩展，未验证前不宣称支持特定 @ 语法。

## 6 两包独立升级与验收

UI 与 knowledge 独立维护版本，清单记录支持的控制契约与 feature。只升级一个包仍必须拒绝不兼容组合，保留数据及设置。UI 控件不包含旧 OS 账号或私有 IPC。

至少验证：

1. UI 单独安装仍正常，缺 knowledge 时给出真实安装入口。
2. knowledge 安装但数据库未就绪时，控件无假就绪，维护页仍可打开。
3. 新会话默认关闭，两个会话独立，重开会话恢复正确。
4. 开启、修改、关闭与真实原生工具作用域一致，没有重复控件或全局查询工具泄漏。
5. 查询中关闭或撤权，旧结果不交付；切会话的迟到响应不覆盖新会话设置。
6. 原生 Harness 可以在选定范围内查询及重读引用，无关对话无需查库，关闭后不再查询。
7. 知识包启停、UI 启停、服务断连、空间删除、失败重试和不兼容版本状态准确。
8. 读取选择不授予写权限，暂停来源扫描不影响已授权只读查询；用户原件与 DSH 原会话保留。
