# 生态插件适配与准入要求

状态：2026-10-28 评审基线，是[开发标准](plugin-development-standard.md)的公众生态补充。适用于人工、Codex、DSH 创造模式及其他开发工具；开发工具不决定插件权限或合格等级。本文件规定应达到什么，不代表市场、第三方安装策略和认证服务已经实现。现行机器标准仍为1.1.0，运行契约仍v1；后续字段变化须正式版本化，不能把本文的新概念直接写入现有清单。

## 1. 三方职责和适配目标

需求、作者协作、客户验收、许可与收益统一沿[共创生态模式](../docs/ecosystem-model.md)。本文件只维护技术准入；作者身份与发行权限分开，客户验收不能替代G4公开发行。

| 对象 | 负责 | 不由其他对象替代 |
| --- | --- | --- |
| DSH | 原生装配、Agent、会话、模型、工具／技能执行、审批、压缩及子代理 | 插件不能复制执行循环、替换宿主安装文件或绕开审批 |
| Beelli X 中台 | 自有环境、登记、配置、场景归属、公共能力及管理页面 | 市场账号不等于业务授权，中台不另做工具执行器 |
| 插件市场 | 发布者、目录、发行审核、制品、兼容信息、获取及更新资格 | 市场展示或付费资格不能证明代码安全、业务正确或DSH已授权 |
| 插件 | 其承诺的业务、资源贡献、数据及维护责任 | 不向中台请求任意文件／数据库管理权限，也不接管其他插件 |

必须区分三种交付：原生DSH插件只证明DSH适配；中台托管插件同时满足DSH和中台契约；UI引导包是原生安装并接入中台的特例。不能把任意DSH插件直接收录为中台兼容，也不能把托管业务包再次登记成Profile独立Bundle。发行和安装规则沿[分发设计](public-plugin-distribution.md)及[加载契约](managed-package-loading.md)。

## 2. 通用规则

以下编号用于需求、测试和审核交叉引用。必选规则适用于所有插件；条件规则仅在插件具备该功能时适用。不适用须有原因和包清单依据，不能用“不适用”跳过核心功能。

| 编号 | 规则 | 交付依据 |
| --- | --- | --- |
| E01 身份和来源 | 稳定包名、插件ID、发布者、来源及维护地址；官方、社区适配、用户生成分别标注。第三方应使用自己的可核验命名空间，不能要求所有作者冒用@beellix。原生贡献ID有归属且冲突时拒绝装配。名称相似不构成更新或接管资格。 | 包清单、发布者身份核验、来源／派生记录及冲突用例 |
| E02 兼容和版本 | 分开声明执行引擎、桌面客户端能力、中台桥接、公共服务、平台／架构和数据代次。声明范围不冒充逐版本实测。公开发行保持包名＋版本不可变；废弃接口给出替代、期限及迁移说明。0.1.1固定策略只约束当前自有包，不约束第三方。 | 兼容矩阵、精确测试环境、变更和迁移说明 |
| E03 工程和制品 | 源码、运行包、用户资料分离；显式入口、打包白名单、锁文件、依赖及组件来源。安装脚本、原生程序和运行时下载须声明，不能依靠未披露的postinstall完成核心功能。离线包说明已包含和缺失组件。 | 源码／依赖摘要、最终tgz文件清单、第三方通知及离线结果 |
| E04 运行和生命周期 | 使用DSH公开装配及执行接口，客户端和host边界清楚；加载仅登记，业务初始化由明确操作触发。取消、停用、升级和退出释放贡献及任务；外部长期服务说明所有者和退出策略。 | 最终包加载／调用／取消／停用／重启／释放测试 |
| E05 中台和依赖 | 使用公开SDK、槽和中台分配目录。区分构建依赖、装配依赖、运行服务；必需服务缺失或未就绪要阻断相应功能，可选服务有真实降级。不得复制数据库、知识库或另一份UI入口充当依赖。 | 公共接口与features清单、依赖就绪／故障／重连接入结果 |
| E06 Agent和上下文 | 工具输入输出、读写属性、取消、超时、有限重试、幂等和错误语义明确；工具／技能按作用域开放，正文按需加载，结果有界并附来源。外部资料不能提升为系统指令；子代理从真实上下文取得受限身份。 | 正常、参数错误、重复写入、取消、越权、超量与来源引用用例 |
| E07 权限与隐私 | 分开记录执行、业务和商业资格。说明访问的文件／服务／网络、读取／写入、资料上传、遥测及保留期限；凭据不进包、日志和提示词。权限声明不是OS沙箱，不能宣传本地插件天然安全；实际执行和服务端再次校验。 | 数据流说明、权限用例、脱敏日志、网络范围和撤销后的验证 |
| E08 数据与恢复 | 数据归属到插件及业务账套／空间，不能从cwd猜归属。配置、原件、派生索引、缓存、业务库和备份分开；迁移不可篡改，写入冲突可识别。规定导出、卸载保留、恢复与降级边界，破坏性操作不由模型自报授权。 | 数据模型、迁移及恢复演练、跨插件／账套隔离、导出和卸载结果 |
| E09 模型与外部服务 | 声明实际用途、必需性、能力、凭据引用、上传范围、费用来源和可选本地路径。主对话沿DSH；插件专用模型统一配置，一个插件一个标签。模型／解析结果有质量样本和失败处理，不能用协议模拟替代真实模型验收。 | 模型声明、真实样本／来源／指标、超时停用与未配置结果 |
| E10 界面和可用性 | 沿宿主主题、语言和公开槽；名称、状态、主要动作清楚。无重复配置、嵌套客户端或虚假指标。覆盖宽窄、日夜、键盘焦点、可读性、加载／空／失败／取消；不以颜色作为唯一状态提示。 | 依[DESIGN.md](../docs/design.md)形成的界面和操作证据 |
| E11 质量与资源 | 需求逐条对应行为证据，测试最终制品；声明适用平台及资源要求。记录代表性资料规模、延迟、内存／磁盘和上下文上限，耗时工作可取消且不阻塞输入。无UI／模型／持久数据的插件不强加对应重型测试。 | 需求覆盖表、规模和资源实测、输入摘要与最终包摘要 |
| E12 发行与维护 | 提供真实介绍、主要类型／业务分类、截图（有UI时）、许可、支持范围、变更、已知限制及问题报告方式。审核、发布、撤回分开，更新不静默扩大权限或覆盖资料；免费与付费采用相同技术门槛。 | 发行资料、审核记录、升级／恢复说明和维护责任人 |

## 3. 类型附加规则

| 类型 | 必需附加规则 | 可不包含 |
| --- | --- | --- |
| 场景包 | 场景绑定、standard基础组成、业务与执行目录分离、原生会话归档、限定右侧工作台、任务产出和业务记录规则；UI和工具走同一领域服务 | 不需要的数据库、知识或专用模型 |
| 工具包 | 参数与输出契约、权限、副作用、取消／重试及正确性；通用工具不伪造场景绑定 | 没有管理需求时的独立页面 |
| 技能包 | 使用条件、所需工具／能力、操作步骤、按需参考和真实任务结果；不能只靠名称承诺专业能力 | 未使用的host服务和数据库 |
| 能力包 | 版本化服务、调用方身份、并发、隔离、健康／初始化状态、停用及依赖故障行为；对外文档与类型一致 | 与该服务无关的业务工作台 |
| UI扩展 | 插槽范围、主题／语言、键盘、冲突处理及卸载恢复；不能冒用引导包或原生面板身份 | 智能体工具和业务数据库 |

独立UI商品的现行中台身份尚未实现，属于阻断项，不因补齐UI测试即可发布。一个包可贡献多种资源，但只有一个主要运行身份。分类是发现用途，不能决定实际权限。

## 4. 合格状态与证据

| 门禁 | 判定内容 | 不能替代 |
| --- | --- | --- |
| G0 输入明确 | 功能、边界、依赖、目标和验收已定义 | 用户授权或真实API存在 |
| G1 静态合规 | 描述、运行清单、工程及打包边界一致 | 构建、运行、安全审计 |
| G2 DSH适配 | 最终制品在明确原生宿主正常加载、调用、取消、重启及释放 | 中台接入与业务正确性 |
| G3 中台与业务 | 安装／启停／初始化／升级归属正确，类型附加规则与核心需求通过 | 真实发行或日常采用 |
| G4 市场发行 | 发布者、许可、发行完整性、审核及获取方式具备；完成适用G0—G3 | 恶意代码绝对安全或所有宿主版本通用 |

这是一套验收分层，当前没有自动签发认证标志的服务。开发中、静态通过、隔离验收、正式发行、实际采用分别记录；失败、未执行与不适用分开。证据绑定输入、工具链、测试环境、最终制品SHA-256、时间及执行者；代码／锁文件／制品改变后重做受影响门禁。由模型生成的“通过”文本不能冒充检查器或运行回执。

公共SDK发布应列明稳定／实验性／废弃接口、版本范围、错误、样例和兼容测试，不让外部作者查私有源码猜API。不承诺尚未公开的服务方法。站点审核和适配标记不能替代用户自己的运行授权。

## 5. 当前落实与准入阻断

| 项目 | 当前事实 | 扩展生态前的要求 |
| --- | --- | --- |
| 自有包适配 | 已有原生装配、中台托管、公共能力／模型契约和描述／工程检查 | 持续以最终包及明确宿主版本验证，不扩大实测范围 |
| 第三方身份 | 工程Schema及安装源仍限制@beellix，部分能力ID保留给官方提供方 | 发布者核验、命名空间与贡献冲突规则、安装策略及迁移协同完成后开放；不只放宽正则 |
| 开发配套 | 有规则、类型和描述样例，未形成全部类型的完整可运行模板／独立公共SDK发行 | 至少先交付工具包和场景包的可复现入门链路，再逐类型开放 |
| UI商品 | 目前无通用运行身份映射 | 完成清单、槽权限、装配／卸载及兼容测试后开放 |
| 市场发行 | 官网已有本机闭环；正式代码包安全发行、生产签名及真实客户端联调未交付 | 对应服务及客户端验证完成前，不称正式公网生态市场 |
| 依赖和迁移 | 有声明和专项服务，未完成通用依赖／业务迁移协调 | 缺失能力阻断；不从清单通过推导全自动安装或升级 |

本规范只定义共同交付格式，不放宽安装信任边界、不启动批量开发或发布、不切换日常客户端。Codex与DSH创造模式的共同任务和逐包证据见[统一开发任务与验收](plugin-development-task.md)。

## 6. 应用互通附加规范

E05／E07／E08涉及其他应用时同时遵循[本机主用户与数据访问](../docs/personal-data-permissions.md)和[跨插件互通](cross-plugin-integration.md)I01—I12及X01—X08。当前本机主用户默认全权，使用ctx.beellixData发现和调用真实提供方，不新增插件结对或人员授权表。各插件保有独立业务库及领域责任，不靠共享表、场景ID或商业会员身份授权；保留业务审核、幂等、知识范围、停用与子代理约束。旧映射仅兼容保留，多人团队的身份与授权须另行实测，不以本机owner证明多人隔离。
