# 插件公开发行与更新契约

本规范区分源码公开、安装包发布、市场收录和服务上线。社区入口 `@beellix-ai/dsh-beellix-plugin` 为0.1.1、MIT；其他插件按自身声明核对许可。源码开放不自动提供官网、账号、下载站或云服务。

## 发行内容

| 内容 | 必需条件 |
| --- | --- |
| 源码仓库 | 真实源码、维护者、许可、第三方署名、安装和开发说明、可复现的依赖锁 |
| DSH 入口 | 顶层 `engines.dsh`、`dsh.bundle.patch`、已提交补丁、有效宿主入口；有前端时声明 `dsh.client` |
| 安装包 | 确定的包名与版本、预构建运行文件、包清单、说明和许可；排除密钥、资料、开发缓存及无关产品 |
| 市场条目 | 客观的中英文说明、合理分类、源码及安装目标；遵守各市场投稿规则 |

第三方实现保留原许可与来源，不把它重新上传为无署名的自有作品。业务数据、客户资料、凭据及未经授权的私有代码不能进入公开包。

## 包身份与不可变发行

一个正式发行由包名、版本与制品摘要共同确定。同名同版本相同摘要可识别为已安装；同名同版本不同摘要不能作为公网自动升级覆盖。

当前0.1.1的本地维护候选可通过用户明确导入处理，但不等于 npm 允许覆盖相同版本。后续正式版本由维护者统一批准；开发示例中的测试版本不改变产品版本。

源代码提交、已构建制品和客户端实际安装分别记录。修改仓库文档不代表运行中的旧安装自动更新。

## 本地包与 npm 安装

本地包先检查包结构、身份、运行契约、依赖和摘要，再展示确认信息；安装成功后由中台登记并通过原生 Include 加载。安装、升级、停用及失败恢复沿[中台加载契约](managed-package-loading.md)。

npm 安装目标须对应真实发布的包，解析版本后固定确切版本与摘要。限制下载来源、超时和体积，拒绝未知身份、结构不符及不可信生命周期行为；不把任意 URL 当作 npm 注册表。

社区中台只在 DSH 安装入口；中台管理的业务包由独立插件环境管理。分类不赋予权限，安装成功也不等于数据库、模型和业务初始化已完成。

## 更新目录

发布目录由入口包维护者预置，不让用户手填更新 URL。当前配置见 `src/update-distribution.mjs`（社区源码目录内），`sourceUrl:null` 表示服务未上线；此时不联网、不伪造检查成功，也不把断网解释成已经是最新版本。

当前清单结构见[发行目录Schema](schemas/plugin-release-catalog-v1.schema.json)：

- 顶层包含 `schemaVersion`、递增的 `sequence`、UTC `publishedAt`、`expiresAt` 与 `packages`。
- 每个包包含确定的 `name`、`version`、`notes`、`distribution`、`bridge` 和 `dataSchemaVersion`。
- 公开安装目标提供 `artifact`，含 HTTPS `url`、`sha256` 和字节 `size`；手工交付目标不在公开清单暴露受限制品。
- 校验原始结构、有界体积、有效期、序列及兼容要求。未知字段和异常结果不能被转换为可更新状态。

可用更新须由用户确认，再验证下载内容与包内身份。数据版本变化不交给通用按钮隐式处理，必须进入该业务包的迁移流程。元数据自动检查不授权自动安装、迁移或执行任意脚本。

当前实现只有 HTTPS、清单约束和摘要完整性校验；**尚未实现可信签名、密钥轮换、渠道撤回和正式公网更新服务**。摘要不能独立证明发布者身份，这些能力须分别完成后才能宣称正式上线。

## 官网账号预留

社区免费本地功能不依赖官网登录。当前 `src/account-distribution.mjs` 未配置发行者，账户适配器为空；不伪造账号、会员或登录完成状态。

未来如接官网授权，可信适配器负责浏览器授权、PKCE、发行者与主体校验，以及令牌刷新和撤销。客户端不能接受前端自报的会员身份或资格；返回结构通过不代表协议签名已验证。令牌沿宿主凭据服务处理，不回传模型，不放入页面状态或日志。

已预留的只读资格结构不等于已经上线会员权限、企业身份或支付服务，不得用它阻止现有 MIT 本地功能。

## 发行验收

1. 从公开仓库独立安装锁定依赖、构建并测试。
2. 检查最终归档清单及第三方许可；在空环境验证 npm/pnpm 安装和原生入口。
3. 按目标 DSH 版本验证加载、调用、停用、卸载及资料保留。
4. 分别记录真实模型、完整桌面和业务质量；模拟或静态检查不代替它们。
5. 核实 npm 权限、不可变版本、市场要求和真实服务状态，再发布对应渠道。

具体市场规则及当前进度见[市场适配](../docs/marketplace.md)，社区源码验证范围见[验证说明](../docs/verification.md)。
