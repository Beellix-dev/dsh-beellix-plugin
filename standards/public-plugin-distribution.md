当前运营主线见[共创生态模式](../docs/ecosystem-model.md)：免费接入、需求协作、按约交付、获准发行和持续维护先闭环，再验证作者收益。下文账号、下载与更新是交付支撑；会员、设备许可和组织服务只按对应作品条款及实际接入启用，不作为参与共创的前置条件。

2026-10-28 当前方向：建立自有 BEELLIX 插件市场，服务 DSH 适配插件；官网与中台的发布目录、账号及资格按真实接口联调。用户已要求删除旧网站，唯一官网工程改为 Web，保留该目录现有风格。旧网站服务的历史实现不代表新官网已接账号、下载或客户端更新；中台侧隔离候选也不等于公网服务交付，不改变本地业务运行、资料归属或现有免费 MIT 许可。

UI入口插件是 **dsh-BeelliX-plugin**，npm包名 `@beellix-ai/dsh-beellix-plugin`，当前固定版本 **0.1.1**，用户确认免费MIT。数据库与场景插件名称保持，各包单独确定免费或商业授权。版本号只在用户明确要求时更新。实际采用只查交付状态，不从文档或版本号推断已切换、发布npm或上线网站。

## 发布结构

建议先采用以下三个边界，不建设一套新的智能体执行系统：

| 部分 | 建议位置 | 公开内容 |
| --- | --- | --- |
| UI入口 | 独立公开仓库 `@beellix-ai/dsh-beellix-plugin` | MIT源码、DSH入口、SDK、安装文档、发行包 |
| 插件目录与官网 | 公开仓库 `beellix-plugin-catalog`，可附静态网站 | 包名、当前版本、功能说明、兼容性、授权、免费安装源或付费获取方式 |

本地开发仍可在当前Beellix目录集中管理；公开仓库通过明确的发布导出流程取得应公开内容，不把包含付费包和本地资料的整个工作区直接公开。

市场先收录维护者审核并适配的插件，开放需求与贡献协作；投稿不自动上架。首期可由平台审核并代发作者授权成果，作者、发行者和维护者分别记录，保留来源与署名。第三方自有命名空间安装和自动发行须待技术准入具备后开放。官网与中台消费同一已发布目录，不分别维护两套版本表；网站账号不承接客户业务数据库或智能体执行。

面向公众的准入要求统一见[生态适配与准入](ecosystem-conformance.md)：E01—E12、类型附加规则及G0—G4。Codex、人工与DSH创造模式使用[共同任务和验收格式](plugin-development-task.md)，来源不改变技术门槛。现行Schema／安装源仍限定@beellix，第三方发布者、命名空间及冲突隔离未完整交付，不能将该内部限制当作公众必须使用的包名，也不能声称现已支持任意第三方中台安装。公开SDK、可运行模板和市场审核需随实际能力逐项开放，当前文档不授予认证标记。

## 安装链路

用户先从DSH原生插件入口安装UI包。免费业务插件从Beelli X中台发现并进入已有包源预检、摘要核验和安装事务；收费业务插件只公开介绍与获取方式，付款后发送安装包，由中台本地导入。两者都安装到初始化的Beellix目录，沿DSH原生Bundle、工具和技能服务运行。

公网目录到发现页的下载接入尚未部署；不能把本地目录或测试夹具当成已上线市场。目录记录需要包名、确定版本、DSH兼容区间、授权、制品完整性和安装方式。付费条目不填公开安装包URL，也不在公开仓库提交收费包。站点、仓库名称与域名均是建议，尚未注册或创建。

## 用户注册与三类权限

账号规划包括注册、身份验证、登录、退出、找回和会话撤销。官网与中台共用一个账户身份；客户端通过系统浏览器完成授权，采用授权码加 PKCE，校验 state 和回调，令牌保存在宿主凭据服务。登录回调能力须按实际 DSH 环境验证，不在中台重复存储用户密码或内置客户端密钥。参考 [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252) 与 [OAuth 安全实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700)。

### 官网账号与会员接入约定（2026-10-28）

用户确认：官网及账号后端暂未建设。目标是在中台首页发起登录，跳转官网验证，验证完成返回客户端；官网后续管理会员及部分插件的获取／使用资格，客户端登录状态须持久化。**本轮已实现首页入口、宿主凭据持久化生命周期及只读资格接口，使用隔离账号适配器验收；真实官网、授权协议与回调尚未接通，未切换现用客户端。** 不创建临时本机密码体系、不伪造官网地址、账号或会员状态。

#### 职责与页面

- 官网负责注册、登录验证、账户安全、会员状态、插件资格及撤销。客户端只发起授权及展示结果，不收集或保存官网密码，不使用 DSH／DeepSeek 账号冒充 Beelli X 账号。
- 首页右上只保留紧凑账号入口。未登录为“官网登录”；等待授权可打开官网或取消；已登录显示昵称、会员标记和“退出”，不再套账户菜单。官网未建时禁用入口并显示“登录 · 待上线”，不显示假会员。首页之外不重复放登录卡。
- 服务尚未上线时如实显示未上线，不生成虚构跳转或“已验证”状态。官网地址、身份服务与客户端标识由维护者随入口包发布，不让终端用户填写地址或密钥。
- 本机仍是单主用户默认全权。官网身份用于会员和插件资格，不另建本机人员／角色授权页。切换官网账号不能自动转移或改写本机账套、会话和资料。
- 首页删除“应用 · 正常／应用管理”重复卡片；安装管理沿左侧导航。只有接入失败、待接入或待重启时才显示简洁状态及必要重试，目录检查仍在折叠维护区。

#### 当前本地接入契约

维护者唯一接入点为 `packages/platform/community/src/account-distribution.mjs`。发行配置含 `schemaVersion:1`、`issuer` 与允许的 `authorizationOrigins`，当前 issuer 为 null、provider 为 null，既不联网也不读写账号凭据。官网上线后由维护者实现 `createWebsiteAccountProvider(ctx)`，不得让插件或前端注册任意登录提供方。当前没有可被网页提交身份／令牌的回调接口。

| 宿主适配器方法 | 返回与责任 |
| --- | --- |
| begin({signal}) | 返回服务器尝试 id、HTTPS url、最多10分钟的 expiresAt；适配器保存 PKCE、state、nonce 等协议状态 |
| poll({id,signal}) | 返回 pending 或 complete＋已由可信官网验证的 session；本机 UUID 与服务端 id 分开 |
| refresh(session,{signal}) | 验证并续期同一 subject，返回完整新 session；凭据轮换在原生原子修改内执行 |
| revoke(session,{signal}) | 撤销官网会话；断网不妨碍先删除本机记录，界面不虚报远端已撤销 |

session 包含 subject、displayName、accessToken、refreshToken、expiresAt、可空 membership 及 entitlements。membership 只有 label／expiresAt；每项 entitlement 为 pluginId、download／update／run 动作及可空 expiresAt。session 的结构校验不等于官网签名验证，**协议验证必须由未来可信适配器完成**。返回状态不接收前端自报的身份或会员等级。

凭据仅使用 DSH `credentials` 的 readRecord／modifyRecord／deleteRecord，记录键 `beellix-ui-bootstrap/website-account`，payload 带 schemaVersion 和 issuer；不创建第二份账号库或写业务目录。首次授权持久写入成功后才显示已登录；重建宿主先调用 refresh 验证再恢复；断网只保留凭据与账号名称，隐藏旧会员且只读资格接口不放行。明确要求重新登录时清除敏感 session；其他 issuer 的记录不覆盖。取消、退出与重载中止在途尝试，晚到结果不得复活登录。

| 本地接口 | 当前职责 |
| --- | --- |
| GET /beellix/account/state | 主用户连接读取脱敏状态与操作令牌，不暴露凭据、subject 或资格全集 |
| POST /beellix/account/login、poll、cancel | 经过原生 owner 鉴权及独立操作令牌发起／推进／取消官网授权；poll 仅接受当前 attemptId |
| POST /beellix/account/refresh、logout | 续期或退出，只清理本服务记录，不改业务资料 |
| ctx.beellixAccount.snapshot()、eligibility({pluginId,action}) | 冻结的宿主只读服务；类型见 packages/platform/community/src/platform-api.d.ts，不提供凭据或登录写入口 |

前端不保存令牌到 localStorage，不发送密码或业务资料。所有修改限4 KiB JSON，错误脱敏，不开放接收 session 的 callback。**资格接口目前只预留查询，未接下载、更新或运行拦截**，不得据此宣称会员插件已受控。原生 credentials-local 的文件保护仍需在真实官网接通前完成专项验收，当前不宣称系统加密存储。隔离测试使用 example.test 与合成令牌，无真实官网账号或旧 Key。

#### 授权与持久化

1. 中台通过已鉴权的 DSH 主用户连接请求登录；宿主生成一次性的授权尝试，通过系统浏览器打开官网。网站采用公开客户端的授权码加 PKCE；具体 issuer、client_id、端点及回调允许列表须与真实官网一起确定。
2. 宿主校验回调来源、state、一次性有效期和授权响应；身份协议需要时同时验证 nonce、发行者、受众和签名。取消、重复、过期或来源不符的回调不能恢复已取消登录。单有浏览器“成功”页面不算客户端已验证。
3. 账号的稳定身份使用发行者与用户ID，不以昵称、邮箱展示文字或本机owner字符串代替。中台前端只拿脱敏账户状态，访问／刷新凭证留在宿主，不进入模型上下文、网页 localStorage、URL日志或安装包。
4. 记住登录需持久保存可续期授权；重启读取后恢复，令牌到期由宿主刷新，官网明确拒绝或撤销后转为需要重新登录。刷新轮换与并发刷新必须原子处理；不能用本地 `loggedIn:true` 或会员等级字符串作为验证结果。
5. 复用 DSH 凭据接口隔离敏感记录与普通账户显示信息。源码中的 credentials-local 是文件型持久存储，不能据此宣称已实现系统加密库；正式接入必须验证实际保护方式，完成系统安全存储或等效的敏感凭据保护。复制业务目录不应把设备授权当作可跨机器复用的登录凭据；必要时重新官网登录。
6. 退出立即取消刷新和当前授权尝试，清除本机可复用凭据及该账号资格缓存，并向官网撤销会话。断网时仍先完成本机退出；远端撤销未完成如实记录，不能重新载入旧凭据或宣称官网已经撤销。退出不删除业务资料、插件或合法许可。

#### 会员资格与本地使用

会员等级是展示信息，插件资格是官网给出的具体结果。一个会员账号可能只获得部分插件；不能仅按“会员=true”开放全部收费包。官网统一提供当前账号及资格，中台统一消费，插件不得各自建第二套官网登录或收费授权记录。

每项资格区分获取、更新、运行及有效期：免费、一次性购买、会员期间使用可采用不同政策。到期是否停止运行由插件正式许可政策明确，**用户尚未确定统一到期规则，当前不实施自动停用已安装插件**。免费MIT及原有已授予权利不因新增会员体系收回。

- 受控下载及更新由官网服务端重新检查账号、发行和资格，客户端按钮不是最终授权。账号凭据不得转发到制品域。
- 若某插件采用有效期内运行许可，宿主、业务接口、原生工具与后台任务必须使用同一有效资格，不能只禁用UI。该机制待网站、正式许可政策及运行契约共同完成后实施，不在当前清单编造会员字段。
- 离线不等于注销或官网明确拒绝。离线是否允许新运行，以及离线许可的范围／期限必须明示；无有效资格不能据旧展示缓存取得新的受控下载。不能承诺离线状态实时收到官网撤销。
- 验证只发送账号、客户端授权及必要插件资格信息；本地知识库、客户、财务、附件和会话正文不随登录上传。资格到期或验证失败不删除资料；查看／导出与恢复边界随正式许可明确，不以清空数据迫使续费。

#### 接通验收门禁

| 检查 | 必须取得的真实结果 |
| --- | --- |
| 首次登录 | 系统浏览器官网验证、可信回调、客户端取得同一稳定账号；不把模拟身份当真实官网 |
| 状态持久化 | 正常重启、UI插件重载后恢复；有效期与官网一致，敏感凭据不出现在前端、日志、提示词及普通备份 |
| 续期与撤销 | 并发刷新、刷新轮换、到期拒绝、退出及远端撤销；失败不把旧会员状态当有效资格 |
| 回调与账号隔离 | 取消、过期、重复、错误state／发行者／受众；切换账号后不沿用旧资格，不改本地资料 |
| 会员插件 | 匿名／普通／会员／过期账号，对获取、更新及已确定的运行规则逐项验证；服务端拒绝不能由UI或工具绕过 |
| 未上线与离线 | 无服务、超时、网络错误、有效离线许可、过期许可分别显示；不伪装登录成功、不锁毁本地资料 |

在真实官网、回调和凭据保护验收完成前，不将入口包安装到现用客户端冒充“官网登录已完成”。客户端与官网后端须按同一协议联调；会员付费、组织及插件运行许可各自按实际范围交付，不隐含为登录本身已实现的能力。

| 权限 | 解决的问题 | 校验位置 |
| --- | --- | --- |
| 插件获取和更新资格 | 用户或组织能下载哪个插件、使用哪些渠道、可获取哪些日期或版本的更新 | 市场服务端按 entitlement 逐次校验；不能仅隐藏按钮 |
| 业务权限 | 企业管理员、成员在客户、资料、账套中可以查看或修改什么 | 对应插件业务服务按组织和资源校验，不用市场角色代替 |
| DSH 执行权限 | 工具调用、文件操作、终端与子代理能执行什么 | 保留 DSH 原生审批和插件已有服务端作用域限制 |

账户、组织、成员、角色与权限、插件、发行记录、授权记录、安装实例、发布审计是不同实体。角色映射到权限，授权记录至少关联用户或组织、插件、可用渠道、更新截止或版本范围、状态及修订。维护者发布权限与客户组织管理权限分开；后端逐资源检查，不信任客户端提交的组织归属。

免费 MIT 包的匿名获取和已授予许可不因引入账户而收回；收费包按商业交付约定增加账号下载与更新资格，第一阶段可由维护者人工登记，无需先接支付。更新支持期结束表示无法获取范围外的新发行，不自动卸载或远程停用客户已获许可的本地包。业务权限继续在本地执行；离线期间不能据过期缓存批准新的受控下载，也不因此阻断已有本地功能。资料查看和导出按原有业务授权保留。

“权限更新”分开处理：服务端修改下载资格后下一次请求立即重新校验；中台刷新显示对应状态。企业业务权限变更走业务服务自己的修订与校验。新增工具权限的插件升级须明确展示并沿原生授权流程处理，不能把商业更新资格当成工具权限批准。

## 发行数据与更新判断

官网文案、图片或页面程序更新只改变展示；**正式发布兼容的新插件制品**才可能产生可更新状态。目录版本用于缓存刷新，插件版本与制品摘要用于判断安装差异，三个概念分开。

| 记录 | 必需信息 |
| --- | --- |
| 插件目录 | pluginId、包名、名称、主要类型／分类、介绍、来源、许可、安装管理归属 |
| 不可变发行 | releaseId、包名、确定版本、渠道、发布时间、变更说明、SHA-256、字节数、制品定位、签名及 keyId |
| 兼容声明 | DSH范围、入口桥接契约、平台／架构限制（适用时）、依赖和数据 schema 代次 |
| 发布状态 | draft／published／withdrawn、目录修订、渠道指针；撤回不改写原制品 |
| 本地安装事实 | 包名、版本、制品摘要、启停状态、安装／加载结果、是否待重启 |

签名覆盖包身份、版本、摘要、兼容声明、渠道、发行序号和有效期；客户端使用可信公钥检查来源，校验已见序号与有效期，避免把历史目录回放当作最新状态。新安装实例仍需检查元数据有效期并取得新鲜目录。私钥仅用于发布，不随插件分发；公钥轮换须有可信更新链。SHA-256 用于校验字节完整性，不能单独证明发布者身份。

公网正式发行遵守包名加版本不可变：相同版本相同摘要表示已是该发行，相同版本不同摘要报发行冲突，不自动覆盖。当前固定 0.1.1 的本地候选可继续通过显式导入展示“更新安装包”；这一开发维护行为不转成公网稳定渠道的同版本静默替换。只有用户明确授权变更版本后才发布后续正式版本，不在本轮自行改号。

兼容候选须同时满足已发布且未撤回、所选渠道、宿主／平台／桥接兼容、依赖可用、获取资格及数据升级条件；不能只拿最大版本号。被撤回版本禁止新下载，已安装时提示处理，不远程删除。预览锁定 releaseId 和摘要，安装前再次检查本地版本及摘要、发行状态与资格；预览后的发行或安装事实变化需重新预览。

## 中台更新流程

1. 用户启用在线检查后，启动中台、进入插件管理或点击“检查更新”读取发行元数据；后台建议六小时检查一次，加入随机抖动、超时、退避和取消，复用 ETag，避免多窗口重复请求。该频率是设计默认值，尚未实现。
2. 中台在本地比较已安装清单与兼容发行。公开目录可直接拉取，无需上传完整插件清单、会话、知识资料、业务数据或模型密钥；受控下载只发送所需发行与授权身份。
3. 插件管理顶部保留一个“检查更新”，条目显示当前版本、可用版本及真实状态：可更新、已是最新、宿主不兼容、需要依赖、无更新资格、待重启、检查失败。失败展示上次成功时间，不能把网络失败显示为已是最新。
4. 用户点击条目“更新”，展示变更与必要前置条件；下载指定发行，校验签名、摘要、大小、身份、包契约及归档安全，再送入现有 NativeAddons.importArchive 和安装事务。新增远程传输适配器不放开 RegistryPackages 已有 npm 来源约束。
5. 安装前保存原包与登记，采用互斥及本地事实冲突检查。没有通用数据迁移器时，schema 改变必须阻断并给出专项迁移要求；不能覆盖安装后宣称业务库可自动回退。具备专项迁移时先完成相应备份和恢复验证。
6. 安装后核对登记与加载结果，需要时显示“重启后生效”，正常重启后检查能力就绪。安装、加载、业务可用是不同状态。失败沿已有恢复链处理，恢复失败保留待处理日志；更新不覆盖旧会话、资料或凭据。

第一阶段提供自动发现加用户点击更新；批量更新需先补依赖排序、组合兼容和恢复验收。后续通知推送仅用来触发重新检查，不携带直接执行的安装命令。入口包更新走单独的原生管理流程，不能混入业务包批量事务。

## 网站未建设时的中台接入

用户提醒网站未做，并明确服务地址由 @beellix-ai/dsh-beellix-plugin 配好，不让终端用户配置。本轮不创建网站、域名、发布后台、账号服务或线上安装包，只实现入口包内置清单与原安装事务的接入。唯一维护配置为 `packages/platform/community/src/update-distribution.mjs`，随包构建为 `lib/update-distribution.mjs`；网站未建时 `sourceUrl:null`，用户看到“更新服务尚未上线”，不联网、不跳设置页、不把断网视为已是最新。实际候选与采用仍以 STATUS.md 为准。

插件管理顶部“检查更新”；已安装卡片提供更新状态，进入详情查看版本和变更后确认更新。没有更新地址表单或设置按钮；来源页只保留既有本地交付与 npm／pnpm 信息。本地包导入、同版候选“更新安装包”、npm／pnpm 安装保持。未公布的包显示“未提供更新”，手动交付的收费包只提示导入更新包，不在公开清单暴露收费制品。UI 入口包仍由原生 DSH 管理。

| 本地接口 | 当前候选职责 |
| --- | --- |
| GET /beellix/console/state 或 /updates | 只读已保存状态，不发网络请求 |
| POST /beellix/console/updates/check | 读取配置的公开清单，不下载包、不安装 |
| POST /beellix/console/updates/install | 校验发行与当前包的确认信息，下载后交既有事务 |

所有接口沿原生连接授权；检查与安装还要求管理者身份和中台操作令牌。不再提供 `POST /updates/config`，旧路径返回404，旧 `config/plugin-updates.json` 原样保留但不读取。检查缓存仍在 `data/control-plane/plugin-updates.json`，按入口包的源身份和修订隔离；不写业务数据库、会话或模型凭据。网站上线并由维护者预置后，启动及后台按成功约6小时／失败至少15分钟检查，停用入口终止定时器及在途下载。当前网站未上线，运行不会向更新站联网。随机抖动、ETag、跨设备账户及受控下载仍是后续能力，不能把草案第1步全部标为完成。

未来站点可先提供 发布清单 Schema 对应 JSON。顶层为 `schemaVersion:1`、递增 `sequence`、UTC `publishedAt/expiresAt` 和 `packages`；每包只有一个当前发行，含确定 `name/version`、`notes`、`distribution`、`bridge` 和 `dataSchemaVersion`。公开包还须有 `artifact:{url,sha256,size}`；手动交付包禁止 artifact。数据版本改变时阻断通用升级，交对应插件的专项迁移流程。

清单2 MiB、tgz64 MiB上限；只接受不含凭据、查询参数、片段的公网HTTPS源，制品必须同源，不跟随跳转。DNS在实际TLS连接时检查公网地址，拒绝私网及混合解析；不上传安装清单、资料或Key。比较版本、序号、有效期；同序号变更及同版换包拒绝。下载核对大小、SHA-256、归档、身份、桥接、数据代次和原生DSH兼容；安装事务锁内再检查旧版本与旧摘要，失败沿既有回退。需要重启与运行成功分开记录。

**此接口阶段只有HTTPS传输、清单约束和摘要完整性，没有实现签名发行、可信公钥轮换、发布撤回／渠道及账号资格。** 服务地址由维护者随入口包发布，用户不用选源；SHA不能证明站点发布者身份。正式公网市场上线前须补上文签名和发行治理并验收，再由维护者预置真实源；本轮隔离模拟不冒充正式公网下载或真实网站验收。也不因测试使用0.1.2等夹具而递增自有包版本。
