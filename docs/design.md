# Beelli X 界面规范

用户确定：**无冗余、强设计、功能操作精简**。适用于当前数据库插件和后续自有 UI、中台、场景页面。沿用 DSH Next 的交互与主题，品牌资产来自本工程 assets；不另起一套客户端外壳。

## 操作

- 每个页面先明确一项主要任务，只突出一个主操作。常用动作放到能直接找到的位置，避免相同动作重复出现。
- 常规路径用合理默认值完成；技术参数、已有服务、离线组件等放进设置中的高级入口。精简操作步骤，同时保留原有能力。
- 插件更新服务地址由 dsh-beellix-plugin 预置；用户只检查和确认更新，不展示网站地址配置表单。
- 能直接完成的操作不再套确认弹窗；必要表单和有实际后果的操作使用宿主弹窗，不使用系统原生提示框。
- 保存、复制、完成等操作反馈统一使用页面中央轻提示，不占顶部通栏；成功后自动收起，操作错误可关闭并保留到处理。字段校验留在字段旁，初始化／下载进度留在任务区域。
- 数据库首次使用只称“初始化”：填写一次恢复密码，自动完成下载安装、初始化和启动，展示真实进度。既有自动生成的恢复密钥仍可单独导出；保留旧口令、旧数据与既有备份，不通过隐藏字段绕过数据保护。

## 信息

- 同一信息只表达一次。首页之外不重复放模块大标题、大图标、介绍段、统计卡或空说明卡。
- 一级模块进入后使用统一页签；列表进入对象详情，复杂配置按用途分组，避免把所有功能摊成一张长页面。
- 多项记录用表格，对象集合按需要用卡片。图标传达类型，颜色传达状态；不为了装饰给每段内容加卡片。
- 默认展示用户能理解的名称、状态和下一步；包名、内部ID、工具路径等留在详情或高级设置。
- 未安装、未初始化、运行中、失败分别显示真实状态。进度有真实数值才显示百分比，未配置能力不伪装成可用。

## 视觉

- 强设计体现在层级、对齐、留白、字重、图标和状态的精确组合。控制中性色与少量品牌色，减少无用途的边框、阴影和装饰。
- 页面、页签、按钮、输入框、弹窗复用宿主组件和主题变量；深浅模式同步。紧密内容成组，组间留白清楚。
- 主操作、普通操作、危险操作有清楚区别。加载、禁用、成功、失败、空状态和键盘焦点都必须完成。

## 验收

检查首次使用到完成任务的完整路径、宽窄窗口、日夜主题、失败重试和旧数据兼容。依据真实渲染、真实接口与隔离数据测试，不以静态截图或构建通过代替功能验收。候选包与客户端实际采用版本分别记录。
