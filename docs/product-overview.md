# Beelli X 中台插件 社区版：产品说明

[文档中心](README.md) · [项目首页](../README.md) · [官网](https://www.beellix.com)

## 产品定位

**Harness-Based Agentic Data Engineering — 基于 Harness 的智能体数据工程。**

以数据中台为核心，基于 Harness 执行底座，通过插件化能力驱动个人、团队与企业的 AI 场景应用，构建数据互通的智能执行闭环，实现能力持续复用与生态演进。

Beelli X 的产品目标，是让用户围绕自身业务选择专业场景、接入已有数据、复用公共能力，通过组装形成自己的智能应用系统。Beelli X 中台插件 社区版是这套体系在 DSH 中的连接入口。

## 三层协作

| 层次 | 负责内容 | 协作方式 |
| --- | --- | --- |
| **DSH 执行底座** | 智能体运行、会话、运行上下文、工具、技能、子代理和执行控制 | 在当前任务作用域中加载并执行所需能力 |
| **Beelli X 连接中台** | 插件管理、模型配置、资源接入、依赖配置和场景组织 | 维护接入关系与公共契约，连接执行底座、数据及业务能力 |
| **场景应用** | 业务对象、规则、操作界面、数据处理和专业产出 | 复用底座执行机制，通过公开接口使用基础能力和工具 |

场景插件是可复用业务能力的交付单位。业务处理由场景实现，公共服务由基础插件提供，专项操作由工具插件完成。多个场景保留专业职责，通过中台契约参与同一套系统协作。

## 插件体系

### 基础插件

提供共享服务、数据连接、存储及其他公共能力。核心部分主要由 Beelli X 维护，使场景可以复用稳定的接入、配置与数据服务。

基础插件维护公开接口、兼容要求、生命周期与恢复规则；使用方声明所需能力和实际依赖。

### 场景插件

围绕业务目标组织可直接使用的应用，是生态共创和应用组装的主要单位。

| 二级分类 | 工作性质 |
| --- | --- |
| **经营管理** | 管理持续发生的业务、对象、单据与状态 |
| **专业作业** | 按专业规则完成处理、计算、设计与交付 |
| **内容创作** | 制作、编辑和管理内容成果 |
| **分析研究** | 围绕问题处理资料与数据，形成有依据的分析结果 |

一个场景按主要用途归类，行业、适用对象和能力标签用于进一步检索。UI、工具、Skills、专业提示词和数据结构按需随场景交付，也可通过声明引用公共能力。

### 工具插件

提供具有明确输入、输出和操作边界的可复用执行能力。工具按所声明的接口完成操作，可由智能体或不同场景调用；业务含义和使用条件由相应业务服务维护。

产品分类与运行资源分别描述。界面、技能和专业角色可以是插件内部组成，既有技术类型和兼容清单按运行契约维护。

## 数据互通

### 数据归属

业务记录由负责该领域的服务维护。公共存储与知识能力由相应基础插件提供，各部分保留明确的数据责任。

DSH 保存原生会话与执行记录，业务服务保存业务数据和成果，通过任务与记录引用建立关联。

### 对象关联

跨场景引用保留对象标识、来源及必要版本信息。对象之间的关联、字段对应及变更处理通过公开契约明确，使后续应用能够正确使用数据并追溯业务过程。

### 业务操作

数据读取与业务动作通过提供方公开的接口进行，由提供方校验业务规则、状态和访问范围。界面与智能体共用业务服务，保持记录和处理规则一致。

各插件可以保有独立存储，通过受控接口协作。数据存储隔离与系统内互通分别设计。

### 任务上下文

Harness 运行上下文与持久化业务数据分别管理。任务按需获取相关记录、知识和证据，完整资料留存在对应数据服务中。

结果保存为业务记录或成果后，可供后续任务和应用继续使用。

## 应用组装

应用系统由场景插件及其所需能力共同组成。装配关系需要描述并验证：

| 内容 | 要明确的事项 |
| --- | --- |
| **应用组成** | 选择哪些场景，各自承担什么业务 |
| **能力依赖** | 所需基础插件、工具、模型和外部服务 |
| **数据关系** | 数据来源、对象关联、字段对应及存储归属 |
| **业务衔接** | 允许的动作、业务条件及结果交接方式 |
| **运行配置** | 初始化、访问范围、兼容要求及恢复方式 |

应用套件可以记录上述组合关系，形成可复用的装配方案。用户可以从单一场景开始，按业务需要扩展，实际组合以各插件支持的契约和验证范围为依据。

场景的安装、依赖就绪、数据初始化和跨应用业务验收分别检查；相应接口与要求见[开发标准](../standards/README.md)和[架构说明](architecture.md)。

## 官网与共创

[Beelli X 官网](https://www.beellix.com)承接作品发现、发行获取、需求发布和共创协作；GitHub 仓库维护源码、技术文档、问题反馈和代码贡献。

共创以场景插件为主要建设方向。贡献者将专业知识、业务规则与操作方法实现为应用，也可以提供基础能力或通用工具供其他场景复用。人工开发、开发助手和 DSH 创造模式遵循共同标准。

中台将生态能力接入用户环境，DSH 执行任务，场景与数据服务承载业务及成果。使用中的反馈推动场景维护和能力复用。
